# «Пульт акима» — финальный визуальный и UX-спек

> Проектный спек интерфейса. Реализованное поведение и актуальные скриншоты — в `README.md`. Отличие от спека по решению команды: на Пульте у каждого района свой категориальный цвет; заливка по шкале D используется в режимах легенды (T1…C2, Δ) и на мини-картах Q0 | Q8 и Сравнения.

Визуальный и UX-спек интерфейса «Пульт акима». Все числа ниже — из ТЗ или из расчёта по формуле ТЗ; всё, что помечено «≈», сверить с движком на репетиции; подписи перцентилей берутся из `score-hist.json` на лету.

---

## 1. Концепт и тезис

Стол акима Астаны при дневном свете — дневной штаб: пять реальных районов лежат на столе как живая карта, 14 мер ставятся на землю кликом, и город меняет цвет ещё до того, как решение подтверждено. Один рабочий экран (Пульт), где принимаются все 5 решений и где формула ТЗ буквально написана на стене: `0.7 × D_avg + 0.3 × min D − N_crit`. Всё считается локальным движком за <1 мс, поэтому каждое наведение — это «что если», каждый клик — пересчёт, а проигрывание 8 кварталов — анимация, выведенная из формулы лага, а не нарисованная. Пока набор не собран по правилам ТЗ, число на экране — **предварительная оценка**, и она так и подписана; Score без оговорок появляется только при 6/6 валидатора. AI не считает: агент вызывает инструменты движка, цитирует их числа, и каждая цифра в его записке подтверждена бейджем. Три экрана, отполированных до конца: **Пульт → Вердикт → Сравнение**. Всё офлайн, без тайлов, без Wi-Fi, одна светлая тема.

Что запомнит жюри: (1) карта настоящей Астаны, на которой Нура медленно пульсирует красной штриховкой; (2) призрак-превью «вижу последствия до клика»; (3) момент при проигрывании кварталов, когда штриховка Нуры гаснет прямо на карте, а `− N_crit 2` перечёркивается в `1`; (4) записка акиму, числа в которой подсвечивают график и подтверждены движком.

### 2.3 Motion-принципы

Принцип один: **анимируется только то, что выводится из данных, и каждая анимация отвечает на вопрос «что изменилось»**. Easing `cubic-bezier(0.2, 0.8, 0.2, 1)`. Длительности: 150ms (hover/ghost-откат), 200ms (ghost-вход, fade экранов), 300ms (перекраска районов, гашение штриховки), 450ms (Score spring), 500ms/квартал (playback), 600ms (waterfall stagger суммарно). Всё прерываемо, ничего дольше 1.2s. `prefers-reduced-motion` — всё мгновенно.

1. **Заливка районов** — `transition: fill 300ms` в CSS на `<path>` (НЕ d3-transition: два хозяина DOM поверх React — источник багов). Цвет считается в React через `scaleQuantize`, DOM владеет только React.
2. **Score** — `motion` `useSpring` (stiffness 120, damping 20) на число + `useTransform(v => v.toFixed(2))` — только при подтверждённом изменении набора (клик). Для ghost-превью число **не анимируется**: рисуется пунктиром рядом с текущим (`52.56 → 55.10`), без spring.
3. **Постановка меры** — пин падает на центроид района (`y: −24 → 0`, 250ms spring), от него расходится одно кольцо, обрезанное `clipPath` по контуру района (600ms) — «эффект растекается по району». Одновременно тики бюджета гаснут по одному слева направо (stagger 12ms) — «видно, как уходят 24 у.е.».
4. **Ghost-превью при hover** — карта/матрица переходят в «что если» за 200ms с пунктирной обводкой (stroke-dasharray 4 2) и opacity 0.6 у дельта-чипов, откат за 150ms; debounce 60ms.
5. **Playback 8 кварталов** — скраббер идёт Q0→Q8 по 500ms; на каждом квартале районы перекрашиваются; **пин загорается в квартале L+1** (первый квартал с ненулевым эффектом: opacity 0.35→1 + кольцо-прогресс `stroke-dashoffset`); штриховка критической пары гаснет in-place в квартале, когда I'(q) ≥ 40 (см. п.7 и §5).
6. **Переход Пульт → Вердикт** — fade 200ms всего экрана; Score в шапке Вердикта досчитывается spring от базы 52.56 до итога. Никакого `layoutId`-перелёта.
7. **Единственный idle-цикл** — медленная пульсация штриховки критических пар на карте (период 3s, opacity 0.85↔1, без свечения) пока N_crit > 0. Читается как «тревога», не как «загрузка». **Снятие критической пары — не тост, а изменение in-place:** штриховка гаснет 300ms, строка `− N_crit 2` в формуле перечёркивается и меняется на `1`, у района на 1.5s появляется короткая подпись «S1 40.0 ✓». Никаких плашек по центру.

### 2.4 Анти-паттерны (запрещено)

- Одинаковые скруглённые карточки в сетке; панели — рейки от края до края, разделённые 1px `--line`; скругление только у чипов (4px) и пинов.
- Ничего по центру: композиция асимметричная — каталог слева, карта центр-лево, тяжёлая рейка Score справа.
- Эмодзи, «искры AI», спиннеры, skeleton-мерцание, каретка «печатающей машинки»; маркеры — только mono-ID мер (`M7`) и коды показателей (`S1`); иконки — lucide-react 14–16px только для действий (play, undo, x, move, compare, printer).
- Градиентные фоны, glassmorphism, blur, свечение, тени (только 1px бордеры), фиолетовый, чёрный `#000`.
- Тайлы карт (OSM/Mapbox/Google) и 3D/deck.gl — только векторные контуры + линия Ишима.
- Пончики, спидометры, gauge для Score, «KPI-плитки с иконкой слева», прогресс-бар Score 0–100 (на нём 4 балла невидимы); Score всегда — число + дельта + перцентиль (перцентиль — только для валидного набора).
- Шестиугольные пины, шторка-фотосравнение, тосты «achievement unlocked», odometer на hover.
- Inter/Roboto/Space Grotesk; Unbounded в тексте длиннее 2 слов.
- Лендинг, «Welcome», онбординг, «Поздравляем», конфетти: демо открывается сразу на карте с 52.56.
- Lorem, заглушки, «примерные» числа: все тексты из ТЗ, все числа из движка; никаких захардкоженных счётчиков («270 сценариев») — только из длины реальных массивов.
- Радар-чарты (искажают площадь, дороги, читаются как «дефолтный дашборд»).

## 3. Экраны и user flow

**Flow:** Пульт (база 52.56, Нура пульсирует) → hover меры (ghost) → клик меры «Район» → what-if-дельты на 5 районах → клик района (пин, бюджет тает, предварительная оценка катится) → ×5 → все 6 маркеров валидатора → число становится **Score** (`--ink`, появляется перцентиль) → «Прожить 8 кварталов» (playback, штриховка Нуры гаснет in-place) → «Подтвердить сценарий» → Вердикт (два хороплета Q0 | Q8, waterfall, slope, трасса агента, записка, рекомендация «Применить») → Сравнение (пресеты ТЗ, оптимум, ваш). Экраны — не роуты, а `screen` в zustand (`pult | verdict | compare`) с синхронизацией в `location.hash` (10 строк) для F5.

**Семантика Score (`scoreStatus: 'preliminary' | 'official'`):** ТЗ: «невалидный набор — Score не считается». Пока валидатор не 6/6, движок локально считает **предварительную оценку** по той же формуле: число рисуется `--ink-2`, пунктирным подчёркиванием, с подписью «предварительно · 3/5»; перцентиль (определён только для полных наборов из 694 395) и кнопка «Подтвердить» скрыты; на пустом наборе показывается база 52.56 с подписью «база · 0/5». При 6/6 число становится `--ink`, подпись «ASTANA QUALITY OF LIFE SCORE», появляется перцентиль. `POST /api/score` вызывается **только** для валидного набора; на невалидный бэкенд возвращает причину, а не число. В README отдельный абзац «предпросмотр ≠ Score по ТЗ».

### 3.1 Пульт (главный экран, 70% демо)

**Композиция.** Единый CSS-grid, **спроектированный под 1280×720** и растущий пропорционально до 1440×900 и 1920×1080 (никакого второго лейаута). Строки `[44px header][1fr][120px bottom]`, столбцы `[264px catalog][1fr map][300px score]`. При 1280×720 средняя строка = 556px; при 1440×900 = 736px. Без прокрутки страницы; прокручивается только каталог (одна короткая прокрутка на 720, без прокрутки на 900).

**HEADER (44px):**
- Слева: wordmark «ПУЛЬТ АКИМА» (Golos 600 12px uppercase tracking 0.12em, ~150px).
- Центр: **5 гнёзд решений** (`DecisionSockets`) — пять прямоугольников 108×26, mono 11px: заполненное «M7 · Нура» / «M12 · город» с 3px-полоской направления слева и «×» при hover; пустое — пунктирный бордер `--line` и «— 3/5 —». Клик по заполненному — попап пина. В payload для «Город» `district: null` (ТЗ: «для «Город» не указывается»).
- Справа (~280px): бейдж **«КРИТ 2»** (`--down` пока >0, `--up` «КРИТ 0» когда снято) · кнопки пресетов «Пример ТЗ» / «Дешёвый» / «Сброс» (маленькие, ghost-style). Переключателя темы и `?`-шпаргалки нет.

**CATALOG (левая рейка 264px):** пять секций по направлениям; заголовок секции 20px «ТРАНСПОРТ · 1/2» (счётчик лимита, `--down` при 2/2 — остальные карточки секции приглушаются). `MeasureCard` — строка **44px** (14 × 44 + 5 × 20 = 716px): слева 3px-полоска направления; `M7` mono 11px; название Golos 12px в 1 строку с эллипсисом; справа стоимость `24` золотом mono 13px + тип «Р/Г» 9px uppercase. `LagStrip` (8 сегментов 6×3px, первые L `--ink-2`, остальные `--accent`, подпись «лаг 3 · 62%») и чипы эффектов «S1 +16» mono 10px показываются **только у hover/выбранной карточки** (карточка раскрывается до 68px, соседи сдвигаются `layout`-анимацией). Состояния: `default | hover(ghost) | placing | placed(галочка, приглушено) | blocked`. **Причина блокировки — ровно одна, самая ранняя по приоритету:** (1) «5/5 — снимите меру», (2) «лимит: Соцсфера 2/2», (3) «несовместимо с M3», (4) «+28 → 128/100». Никаких скрытых блокировок и «мигающих» текстов: жюри кликает — карточка объясняет одно.

**MAP (центр, 716×556 при 1280×720):** `MapAstana` — SVG, `d3-geoMercator().fitExtent` с padding 40; фон = `--panel`; районы залиты по шкале выбранного показателя (по умолчанию D), обводка 1px `--line`; линия Ишима 1.5px `--accent` opacity 0.5 — она отделяет Есиль от Алматы, жюри узнаёт город. Подпись района: имя Golos 11px uppercase + под ним mono `62.99` и дельта-чип (появляется при изменении); **Байконур (самый маленький полигон) — только код и число**. Пины поставленных мер: **круг 22px** цвета `--panel` с 3px полосой направления и mono-ID; 2–3 пина у одного центроида — фиксированные смещения (0 / +26px / −26px по x), не «по дуге»; меры «Город» — уменьшенный пин 16px на всех 5 районах. Слои SVG снизу вверх: `districts → hatch(<40) → river → whatif-labels → pins → ghost → selection`. Легенда (левый нижний угол карты, плавающая): сегментированный контрол `D · T1 T2 E1 E2 S1 S2 B1 B2 C1 C2 · Δ` + рампа 5 ступеней + образец штриховки «<40 критично». Hover района — мини-карточка: «Нура · D 49.18 · pop 16% · крит 2 · **слабее всего: S2 35**». Все 50 чисел — в матрице 5×10 (вкладка внизу); отдельного попапа района нет.

**SCORE (правая рейка 300px, при 720 высота 556px, контент ≈ 470px), сверху вниз:**
1. **Бюджет** (`BudgetTicks`, 48px): подпись «БЮДЖЕТ · 100 у.е.» + строка mono справа «остаток **37**» золотом и микроподпись 9px `--ink-2` «остаток не влияет на Score» (ТЗ: не сгорает и не даёт бонуса); полоса из 100 тиков 2×10px с зазором 1px (=300px): потраченные — цвет направления меры, сгруппированы с 2px-разделителем, остаток — золото. Превышение: тики-призраки `--down` выходят за правый край рейки на ширину перерасхода, подпись «+14 → 114/100», полоса вспыхивает 280ms — не модалка. Hover на группу тиков ничего не подсвечивает (вырезано).
2. **Score-герой** (≈96px): подпись 10px «ПРЕДВАРИТЕЛЬНО · 3/5» / «ASTANA QUALITY OF LIFE SCORE»; число `56.54` Unbounded 44–56px, `--ink-2`+пунктир или `--ink` по `scoreStatus`; рядом чип `+3.98` (`--up`/`--down`); под ним **перцентиль** (только `official`): мини-гистограмма 260×32 всех 694 395 валидных сценариев (предпосчитано, `public/data/score-hist.json`), маркер `--accent` на текущем Score, подпись mono «лучше ≈99.92% сценариев · макс 57.24». Это решает главную проблему кейса: диапазон всего 52–57, на шкале 0–100 движения не видно.
3. **Формула** (`FormulaRows`, mono 12px, 3 строки, 54px): `0.7 × D_avg 58.08 = 40.65` / `0.3 × min D 52.96 = 15.89` / `− N_crit 0 = −0.00` — базовые значения рядом зачёркнуты серым (`56.86`, `49.18`, `2`). Формула ТЗ буквально на экране.
4. **РАЙОНЫ** — 5 строк по 22px, отсортированы по pop: имя · pop `27%` (тонкий серый бар — напоминает, что D_avg взвешена) · bullet-bar D 100×6 (домен 40–80, тик базы, заливка до нового) · дельта mono справа · **крит-пары — бейджем прямо в строке района**: «Нура · S1 38 · S2 35» `--down`, зачёркивается `--up` когда снята. Отдельной секции «Критические пары» нет.
5. **ВАЛИДАЦИЯ** (`ValidationStrip`, 24px) — одна строка из 6 квадратных маркеров 12px с tooltip: ровно 5 · без повторов · ≤2 на направление · районы указаны · несовместимости · бюджет ≤100; серый = не проверено, `--up` = ok, `--down` = нарушено. - **Click меры «Район» → режим постановки + what-if на 5 районах** (graft): карточка получает `--accent`-рамку, курсор `crosshair`, на **каждом** районе всплывает mono-ярлык предсказанной ΔScore именно для этой меры здесь («+1.42 / +0.35 / −0.87»), лучший район — обводка 2px `--accent` + подпись «лучший»; недопустимые (несовместимость в этом районе) — красная штриховка + «M7 несовместим с M4 здесь», **клик по такому району заблокирован** (не только подсвечен). Движок считает 5 вариантов за <5 мс. Клик по району ставит, Esc отменяет. **Ловушка M11**: при выборе M11 Алматы показывает `−0.87` красным (T1 40 → 38.25 — новая критическая пара, один M11 Алматы = 51.687), Нура `+0.32` (52.875) — жюри видит «формула наказывает» до клика.

- **Click по пину / гнезду**: попап «M7 Школа + детсад · Нура · 24 у.е. · лаг 3 · S1 +10.0» с кнопками «Переставить» (режим постановки с what-if; несовместимые районы заблокированы так же) и «Снять».

- **Легенда**: переключение показателя перекрашивает карту 300ms; режим «Δ» — дивергентная шкала с числами на районах.
- **Скраббер**: перетаскивание меняет q; при q<8 герой подписан «к кварталу 5 · промежуточно».

- «Подтвердить сценарий» → `POST /api/analyze` (валидация + Score + запуск агента), переход на Вердикт; фронт сверяет Score бэкенда со своим (в dev — предупреждение в консоли при расхождении).

### 3.2 Вердикт (`/#verdict`)

**Композиция.** Шапка 72px: слева «ВЕРДИКТ» (Unbounded 20px) + «Сценарий #1 · 95 / 100 у.е.» + 5 гнёзд; справа Score-герой `52.56 → 56.54` (второе число Unbounded 64px, spring от базы после fade-входа), чип `+3.98`, «лучше ≈99.92% · до оптимума −0.69». Ниже две колонки 54/46, вертикальная прокрутка только правой.

**ЛЕВАЯ колонка:**
1. **`QuarterPair`** (высота 300): два хороплета рядом, «Q0» | «Q8», в одной шкале, подписи районов только mono-числами; штриховка Нуры слева есть, справа — нет. Дешевле шторки и без метафоры фотосравнения.
2. **`ContributionWaterfall`** (160px), **один режим — последовательный в каноническом порядке** (по ID меры, «Город»-меры последними), подпись mono 10px «порядок канонический; вклад зависит от порядка из-за min D и N_crit»: старт `52.56` → столбик каждой меры (цвет направления, mono «M7 · Нура +1.45») → «синергия M10+M12 +0.07» → «снятие критических +2.00» (`--up`) отдельными столбиками → итог `56.54` жирной чертой; **сходится точно**. Leave-one-out-числа («без M7 Score был бы −1.45») — в записку и рекомендации, не в график. Столбики растут stagger 60ms.
3. **`DistrictSlope`** (180px): 5 линий D_d «до → после», толщина ∝ pop, Нура `--accent` (растёт сильнее всех: 49.18 → 52.96), Байконур почти горизонтален серым; подписи mono с двух сторон.

**ПРАВАЯ колонка:**
1. **`AgentTrace`** (полоса 48px, mono 11px): шаги агента появляются по мере выполнения — `validate ✓ · score ✓ 56.54 · contributions ✓ 5 мер · neighbors ✓ {n} сценариев, лучшая замена +0.45 · percentile ✓ 99.92%`. `{n}` — длина реального массива `neighbors()`: одношаговые замены 5 слотов × 45 свободных мер = 225 + перестановки района для «Район»-мер (число из кода, не из спека). Справа на полосе маленький переключатель «офлайн-режим» (шаблон вместо LLM) — ответ на вопрос «что если ключ отвалится».
2. **`MemoDocument`** — записка на `--paper`-подложке (поля 32px): шапка «Кому: Акиму г. Астаны · От: Аналитический штаб · Сценарий #1 · дата» Golos 12px; разделы капителями «ИТОГ», «СИЛЬНЫЕ СТОРОНЫ», «РИСКИ И ПОБОЧНЫЕ ЭФФЕКТЫ», «КОМПРОМИССЫ», «РЕКОМЕНДАЦИИ»; текст Golos 15/1.55 **стримится абзацами** (событие `paragraph` в SSE или разбиение по `\n\n`), каждый абзац fade-in 200ms, без каретки. **Чипы ставятся по завершённому абзацу**: регэксп `[+−\-–]?\d+[.,]\d{1,2}`, нормализация `,`→`.` и `−/–/-`→`-`, сверка с множеством чисел движка с допуском ±0.005; чип — mono с подчёркиванием `--accent`; hover на чипе подсвечивает столбик waterfall / район на Q8 / строку slope (**одно направление**, обратной подсветки нет). Целые числа и константы ТЗ (100, 5, 8, 0.7, 0.3, веса, pop) — whitelist, в счётчике не участвуют. Внизу записки бейдж **«11/11 чисел подтверждены движком»** (`--up`; при несовпадении — «10/11 · 1 не подтверждено» `--down`, число помечено пунктиром). В промпт агента передаётся явный список чисел «копировать как есть, арифметику не делать».
3. **`Recommendations`** — 1–3 строки-карточки от `neighbors()`: «Перенести M3 Есиль → Нура · Score +0.45 → 57.21 · бюджет 0» с кнопками «Примерить» (ghost на Q8-карте и герое) и «Применить» (возврат на Пульт с заменённым набором, изменённое гнездо подсвечено, Score катится).
4. Кнопки: «Сравнить сценарии», «Вернуться на Пульт», «Переанализировать» (если набор изменён); «Бриф акима (печать)» — только если print-бриф успел (§3.4).

**Порядок реализации (критический путь без LLM):** (1) шаблонная записка на числах движка — те же разделы, те же чипы, бейдж «шаблон»; (2) кэш ответов LLM для трёх демо-наборов в `public/cache/`; (3) живой SSE. Демо проходит на (1) в первый день; LLM — надстройка. Fallback: таймаут/ошибка LLM >8s → панель без паузы показывает (1); для демо-наборов — (2).

**Хореография входа (≤1.5s до первого абзаца, играет один раз на новый сценарий):** fade 200ms → Q0 | Q8 уже стоят → waterfall stagger 60ms (0.6s) → slope-линии дорисовываются (0.3s) → Score-герой досчитывается spring → трасса агента печатает шаги → стрим записки. Любой клик или `Space` — мгновенно в финальное состояние; «Переанализировать» хореографию не повторяет, если набор не изменился.
