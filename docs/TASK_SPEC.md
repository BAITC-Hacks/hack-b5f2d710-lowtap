# Хакатон, спец-трек Astana Innovations. Кейс «Аким на 5 часов» — AI-симулятор управления городом


## Проблема
При принятии решений по развитию города необходимо учитывать одновременно несколько направлений: транспорт, озеленение, социальную инфраструктуру, безопасность и качество городских сервисов. Ограниченность ресурсов требует оценки сценариев и понимания, как распределение бюджета влияет на качество городской среды.

## Пользователь
Городской управленец, аналитик либо пользователь симулятора.

## Задача
AI-симулятор: команда получает одинаковый виртуальный бюджет и набор данных о состоянии условных районов города. Пользователь принимает 5 управленческих решений по направлениям: транспорт, озеленение, социальная инфраструктура, безопасность, городской сервис. AI анализирует выбранные решения, их стоимость и влияние на показатели, формирует итоговую оценку сценария и рекомендации.

## Must have
- единый виртуальный бюджет для всех пользователей
- возможность принять решения по 5 заданным направлениям
- автоматический контроль превышения бюджета
- AI-анализ принятых решений
- расчет итогового Astana Quality of Life Score
- объяснение сильных сторон, рисков и возможных последствий выбранного сценария

## Опционально
- сравнение результатов нескольких команд
- визуализация изменений показателей районов
- AI-рекомендации по улучшению выбранного сценария
- моделирование неожиданных городских событий, требующих перераспределения бюджета
- автоматическая генерация краткой презентации решения команды

## Критерии проверки
- Все команды начинают с одинакового бюджета и данных.
- Система не позволяет превысить бюджет.
- Принятые решения влияют на итоговые показатели модели.
- AI формирует понятное объяснение результата и основных компромиссов.
- Изменение набора решений меняет Score.

## Рубрика (100 баллов)

- Техническая реализация (подход, архитектура, взаимодействие компонентов, использование AI/agentic AI; соответствие реализации заявленной логике) — 25
- README и воспроизводимость (устройство проекта, технологии, порядок запуска, основной сценарий; возможность воспроизвести и проверить) — 25

## Формула Score
1. I'_dk = clip(I_dk + Σ эффект_m,k × (8 − L_m)/8 + синергии, 0, 100)
2. D_d = Σ w_k × I'_dk; веса: T1 .10, T2 .10, E1 .09, E2 .11, S1 .11, S2 .11, B1 .09, B2 .09, C1 .10, C2 .10 (транспорт .20, экология .20, соцсфера .22, безопасность .18, сервисы .20)
3. D_avg = Σ pop_d × D_d
4. Score = 0.7 × D_avg + 0.3 × min(D_d) − 1.0 × N_crit, где N_crit = число пар район×показатель со значением строго < 40 после эффектов.
Базовый Score без действий: 52.56 (0.7×56.86 + 0.3×49.18 − 2; критические: S1 и S2 в Нуре).
Пример допустимого набора: M7 Нура, M8 Нура, M10 Нура, M12 город, M5 Сарыарка. Стоимость 95. Score ≈ 56.5.
ПРОВЕРЕНО КОДОМ (python): база = 52.558, пример = 56.543 (N_crit=0, стоимость 95), самый дешёвый набор M9+M11+M10+M12+M4 (все в Нуре) = 55.667, стоимость 61, N_crit=1. Формула понята верно.

Роль ИИ: LLM получает результат расчёта (дельты по районам и показателям, вклад каждой меры) и объясняет его, сравнивает наборы, советует. Числа он не считает и не придумывает.

## Правила
- Бюджет 100 у.е. Остаток не сгорает и не даёт бонуса.
- Решений ровно 5 (не «до 5»).
- Повторы запрещены (каждое мероприятие максимум один раз).
- Для мер «Район» район обязателен; для «Город» не указывается.
- Не более 2 мер из одного направления (⇒ минимум 3 направления затронуты).
- Несовместимости запрещены.
- Невалидный набор: Score не считается, валидатор возвращает причину.
- Порядок решений не важен.
