# Питч «Аким на 5 часов» — команда lowtap

Сценарий показа по кликам — в [DEMO.md](DEMO.md). Здесь тезисы для ведущего и ответы на вопросы жюри. Все числа — из движка и тестов.

## Одна фраза

Симулятор, в котором аким Астаны распределяет 100 у.е. на 5 решений по реальным районам: детерминированный движок считает Astana Quality of Life Score строго по формуле ТЗ, AI-аналитик объясняет результат и советует, а каждое число в его записке сверено с движком.

## Проблема → решение

- **Проблема.** Решения по городу принимаются сразу по пяти направлениям при ограниченном бюджете. Интуиция «вложить в сильный район» проигрывает: формула наказывает за неравенство (0.3 × min D) и за каждую критическую пару ниже 40.
- **Решение.** Пульт, на котором последствия видны до клика, правила ТЗ нельзя нарушить, а итог объясняет AI, которому можно верить.

## Что запомнит жюри

1. **Карта настоящей Астаны** (границы OSM, офлайн). Нура пульсирует красной штриховкой: школы 38, поликлиники 35 — минус два балла ещё до первого решения.
2. **Последствия до клика.** Ghost-превью меры и предсказанная ΔScore на всех пяти районах. Ловушка M11: переходы в Алматы дают −0.87 (T1 40 → 38.25, новая критическая пара), в Нуре — +0.32.
3. **Время.** 8 кварталов по формуле лага: в Q4 у Нуры «S1 40.0 ✓», `− N_crit 2` перечёркивается в `1`, в Q8 — ровно Score по ТЗ.
4. **AI, которому можно верить.** Трасса шагов, записка «Кому: Акиму г. Астаны», бейдж «10/10 чисел подтверждены движком» (в режиме rules — 21/21), рекомендация «Применить» → Score 56.54 → 57.21.

## Как устроен AI (ответ на «а где тут agentic AI?»)

- LLM получает не сырые данные, а **таблицу фактов F1..Fn**, посчитанную движком, и ссылается на них в каждом утверждении (evidence).
- Рекомендации — наборы решений: сервер **перевалидирует и пересчитывает** каждую, помечает `verified` или причину отказа.
- **Guard** сверяет каждое десятичное число текста с фактами (±0.005) и выдаёт `verified_numbers`. LLM не считает Score ни в одном месте.
- Цепочка **llm → cache → rules**: ответ всегда HTTP 200, без ключа и сети записка строится по правилам на тех же числах. В UI это видно по бейджу провайдера и галочке «офлайн-режим».

## Техническая убедительность

- Два движка — Python (истина) и TypeScript (ghost-превью < 1 мс, офлайн). Паритет доказан тестом на **71** golden-кейсе с допуском 1e-6.
- Тесты: фронт — 142 vitest и 2 Playwright, бэкенд — 298 pytest. Эталоны ТЗ, все 12 кодов валидатора, граница 40, clip, синергия без лага, Σ Шепли = ΔScore.
- Невалидный набор → HTTP 422 с причинами, Score не считается ни на сервере, ни в UI (там число подписано «предварительно»).

## Ценность для Астаны

- Показывает, **куда** вложить, а не только **сколько**: те же деньги в Нуру дают +4 балла, а во «всё в Есиль» — +1.45.
- Переводит баллы в людей: доля жителей в районах без критических показателей растёт с 84 % до 100 %.
- Готов к реальным данным: датасет — это JSON с хэшем, формула и веса — в `data/rules.json`.

## Вопросы жюри — короткие ответы

| Вопрос | Ответ |
|---|---|
| Score на трёх мерах — это нарушение ТЗ? | Нет: пока набор не по правилам, число серое, с пунктиром и подписью «предварительно · 3/5», без перцентиля. Score по ТЗ появляется только при 6/6 валидатора, сервер на невалидный набор отвечает 422. |
| Откуда вы знаете, что числа LLM верные? | LLM их не считает: пишет по фактам движка, guard сверяет каждое десятичное число, бейдж показывает N/N. |
| Что если ключ отвалится или нет интернета? | Кэш, затем правила, HTTP 200. В UI — галочка «офлайн-режим» на полосе трассы. |
| Почему таймлайн, если в ТЗ только итог? | Это визуализация лага: эффект × max(0, q − L)/8. В Q8 — ровно формула ТЗ, итоговый Score считается только по ней. |
| 57.24 — точно максимум? | Да, полный перебор всех 694 395 допустимых наборов, скрипт `scripts/enumerate_plans.py` в репозитории. |
| Почему «56.54», а в ТЗ «≈56.5»? | Это то же число: движок хранит 10 знаков (56.543), UI показывает 2. |
